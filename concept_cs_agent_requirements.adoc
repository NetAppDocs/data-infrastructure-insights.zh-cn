= 工作负载安全代理要求
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
在满足最低操作系统、CPU、内存和磁盘空间要求的专用服务器上部署 Workload Security Agent，以确保最佳的监控和威胁检测性能。本指南规定了在 link:task_cs_add_agent.html["安装 Workload Security Agent"] 之前所需的硬件和网络要求，包括支持的 Linux 发行版、网络连接规则和系统规模调整指南。



[[system-requirements]]
== 系统要求

[cols="50%,50%"]
|===
| *组件* | *Linux 要求* 


| 操作系统  a| 
产品中列出的任何 64 位 Linux 发行版，包括启用了 SELinux 的系统。

有关支持的发行版和版本的当前列表，请在 Workload Security 中转到收集器 ++>++ 代理 ++>++ {plus}代理，然后单击支持的 Linux 版本（i）。该列表由产品生成，并且始终是最新的。

安装程序还会验证主机：在不受支持的发行版上，它会停止并显示“不支持此 Linux 发行版。退出安装”。

此计算机不应运行任何其他应用程序级软件。建议使用专用服务器。



| 命令/包  a| 
在 Agent 主机上需要满足以下要求：

* unzip — 代理安装
* zip — 诊断包（cloudsecure-agent-symptom-collector.sh）
* sshpass — 事件速率检查器（svm++_++event++_++rate++_++checker.sh）
* sudo su – — 安装、运行脚本和卸载




| CPU | 4 个 CPU 核心 


| 内存 | 16 GB 内存 


| 可用磁盘空间  a| 
按如下方式分配磁盘空间：

/opt/netapp — 36 GB （文件系统创建后最少有 35 GB 可用空间）

注意：分配一点额外的磁盘空间以允许创建文件系统；确保文件系统中至少有 35 GB 的可用空间。如果 /opt 是从 NAS 存储装载的，请确保本地用户有权访问该文件夹——否则 Agent 或 Data Collector 可能无法安装。



| 时间同步 | 使用 NTP 或 SNTP 在 ONTAP 系统和 Agent 主机上同步时间。ONTAP 和 Agent 之间的时钟偏差会破坏事件相关性、运行状况检查和故障排除。 


| 网络 | 100 Mbps 到 1 Gbps 以太网连接、静态 IP 地址、到所有受监控设备的 IP 连接，以及到 Workload Security 实例（80 或 443）的所需端口。 
|===
Workload Security Agent 可以与 Data Infrastructure Insights 采集单元和/或代理安装在同一台计算机上；但是，将它们安装在单独的计算机上是最佳做法。如果安装在同一台机器上，请按如下所示分配磁盘空间：

[cols="50%,50%"]
|===
| *可用磁盘空间* | *分配* 


| 50–55 GB（组合安装） | 对于 Linux，分配为：/opt/netapp 25–30 GB；/var/log/netapp 25 GB 
|===

[[in-network-rules]]
== 网络内规则

[cols="20%,20%,20%,20%,20%"]
|===
| *协议* | *端口* | *源* | *目标* | *描述* 


| TCP  a| 
389 (LDAP)

636 （LDAPS / start-tls）
| 工作负载安全代理 | LDAP 服务器 URL | 连接到 LDAP。支持 SSL (LDAPS/start-tls)；接受服务器提供的证书。 


| TCP | 443 | 工作负载安全代理 | 集群或 SVM 管理 IP 地址（取决于 SVM 收集器配置） | 与 ONTAP 的 API 通信。 


| TCP | 35000-55000 | SVM 数据 LIF IP 地址 | 工作负载安全代理 | ONTAP 到代理的 FPolicy 事件通信。向代理打开这些端口（包括代理本身的任何防火墙），以便 ONTAP 可以发送文件/用户访问事件。 


| TCP | 35000-55000 | 集群管理 IP | 工作负载安全代理 | 从 ONTAP 集群管理 IP 到 Agent 的通信，用于 EMS 事件（例如，反勒索软件 / ARP）。向 Agent 开放这些端口（包括 Agent 本身的任何防火墙）。 


| SSH | 22 | 工作负载安全代理 | 集群管理 | 需要 CIFS/SMB 用户阻止。 
|===
*关于 FPolicy/EMS 端口范围*

您无需打开整个 35000–55000/tcp 范围。根据 Agent 上的收集器数量调整保留大小：每个 SVM 最多使用 4 个端口（每个启用的协议 2 个 — NFS 和 CIFS/SMB）。对于完全加载的 Agent（50 个收集器），在此范围内保留约 200 个端口，并在必要时增加。上述两行对不同流量使用相同的范围：SVM data LIF → Agent 承载 FPolicy 文件/用户活动事件，而 Cluster management IP → Agent 承载 EMS 事件（如 ARP）。如果使用相应的功能，请同时打开这两条路径。

在添加收集器之前运行测试连接时，它仅验证此范围内的一小部分活动端口。在 Agent 防火墙以及 ONTAP 和 Agent 之间的任何网络路径上保持完整的保留范围处于打开状态。



[[system-sizing]]
== 系统规模估算

代理最多支持 50 个数据收集器（所有类型的总和），上限约为每秒 20,000 个事件。

专用 Agent 主机的典型指南：

* *4 CPU / 16 GB RAM —* 约 10 个采集器
* *4 CPU / 32 GB RAM —* 约 20 个采集器
* *使用其他代理横向扩展* 当接近 50 个收集器或 20,000 个事件/秒的限制时


在添加收集器之前，请使用事件速率检查器（svm++_++event++_++rate++_++checker.sh）测量峰值事件速率。有关完整的大小调整方法，请参见事件速率检查器文档。
