= 删除工作负载安全代理
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
当您停用其主机或将收集整合到另一个 Agent 时，请删除 Agent。删除 Agent 还会删除仍分配给它的每个收集器。

[cols="100%"]
|===
| *删除代理将删除其剩余的收集器* 仍分配给该代理的任何数据收集器或用户目录收集器都将随之删除，并且此后无法恢复配置。在删除代理之前，请记录或移动您仍然需要的任何配置。 
|===


[[decide-what-you-want-to-keep]]
== 决定要保留的内容

[cols="37%,63%"]
|===
| *您的目标* | *操作步骤* 


| 继续从另一个代理收集相同的存储 | 在删除此 Agent 之前，将每个收集器移动到另一个 Agent。重新分配收集器，而不是重新创建它们，以免重复收集。 


| 完全停止从此存储中收集 | 删除 Agent。仍分配给它的收集器将同时删除。 


| 在新主机上重建代理 | 首先记录每个收集器的配置，部署新的 Agent，然后重新创建或移动收集器。 
|===


[[before-you-begin]]
== 开始之前

* 以 Data Infrastructure Insights 管理员或帐户所有者身份登录。删除代理需要管理员权限。
* 按名称识别 Agent，并在 Agent 详细信息页面上查看分配给它的收集器。
* 保存您仍然需要的任何收集器配置。已删除的收集器配置无法还原。
* 从引用此 Agent 的任何警报策略中删除分配给此 Agent 的每个收集器。警报策略仍然引用的收集器会阻止删除。


[cols="100%"]
|===
| *您无需暂停 Agent、取消固定或等待升级* 暂停、恢复、固定和取消固定不会影响 Agent 删除。计划或正在进行的 Agent 和收集器操作也不会阻止它。 
|===


[[choose-the-procedure-that-matches-your-agent]]
== 选择与您的代理匹配的步骤

Agent 列表显示每个 Agent 的状态。删除前必须执行的操作取决于 Agent 是否仍处于连接状态。

[cols="21%,62%,17%"]
|===
| *代理状态* | *Workload Security 需要什么* | *使用* 


| 已连接 | 必须首先从代理中删除每个数据收集器和 User Directory Collector。收集器状态无关紧要；已停止的收集器仍会计算在内。 | 步骤 A 


| 未连接 | 无需先移除收集器。仍分配的任何收集器将与代理一起删除。 | 步骤 B 
|===


[[procedure-a-delete-a-connected-agent]]
== 步骤 A：删除已连接的代理

*1.*选择 Workload Security ++>++ Collectors ++>++ Agents，然后选择 Agent 名称以打开其详细信息。

*2.*移动或删除为代理列出的所有数据收集器。要继续收集相同的存储，请将收集器分配给另一个代理，而不是将其删除。

*3.*移动或删除为代理列出的每个用户目录收集器。

*4.*返回 Workload Security ++>++ Collectors ++>++ Agents。

*5.*选择代理的选项菜单，然后选择删除。

*6.*在“删除代理”对话框中确认删除。

*7.*在其主机上卸载代理软件，如“卸载代理软件”中所述。

image:ws-delete-agent-confirmation.png["删除代理对话框，确认删除示例代理，并显示从其主机卸载代理软件的命令。,title=\"删除代理确认对话框\",width=1007,height=562"]

[cols="100%"]
|===
| *如果对话框显示“无法删除代理”* 至少有一个数据收集器或用户目录收集器仍分配给此连接的代理。移除剩余的收集器并重试。如果您刚刚移除了它们，请先刷新代理页面。 
|===


[[procedure-b-delete-a-retired-or-unreachable-agent]]
== 步骤 B：删除已停用或无法访问的代理

当代理主机正在停用或已经离线，并且不再需要为其分配收集器时，请使用此过程。

*1.*确认您不再需要分配给此代理的任何收集器。这些收集器将随之删除。

*2.*如果主机仍然可访问，请按照“卸载代理软件”中的说明卸载代理软件。

*3.*选择 Workload Security ++>++ Collectors ++>++ Agents 并等待 Agent 显示 Not Connected。

*4.*选择代理的选项菜单，然后选择删除。

*5.*在“删除代理”对话框中确认删除。



[[uninstall-the-agent-software]]
== 卸载代理软件

在 Workload Security 中删除代理将删除其云端配置。它不会从主机中卸载该软件，因此请在淘汰该主机时单独卸载该软件。

*1.*在 Agent 主机上打开终端会话。

*2.*运行卸载命令，并在出现提示时输入 y。

[listing]
----
sudo cloudsecure-agent-uninstall.sh
----
卸载程序停止并禁用 Agent 服务，并删除安装目录。要在没有确认提示的情况下卸载，请添加 -n 选项。



[[verify-the-deletion]]
== 验证删除

* Agent 不再显示在 Workload Security ++>++ Collectors ++>++ Agents 中。
* 分配给它的收集器不再显示在收集器列表中。
* 如果您卸载了该软件，则代理服务不再存在于主机上。




[[troubleshooting]]
== 故障排除

[cols="39%,61%"]
|===
| *信息或症状* | *原因和解决方案* 


| 无法删除代理：“请删除 ++<++Agent++>++ 上配置的所有数据收集器。” | 此代理已连接，并且仍至少分配有一个数据收集器或用户目录收集器。请移动或删除其余收集器，刷新页面，然后重试。 


| "在删除代理之前，请从这些策略中移除该代理的以下设备。" | 此 Agent 下的收集器仍由消息中命名的警报策略引用。编辑每个策略，删除该收集器，保存策略，然后重试删除。 


| 删除失败并出现授权错误。 | 删除代理需要管理员或帐户所有者。其他角色可以打开“代理”页面，但无法完成删除。 


| 系统报告代理未注册。 | 代理已被删除，或者您正在不同的环境中工作。刷新代理页面并确认代理和租户。 


| Agent 已从 Workload Security 中删除，但仍在主机上运行。 | 删除代理不会卸载软件。在主机上运行 uninstall 命令。 


| 已删除的收集器似乎仍在消耗使用量。 | 使用情况由每个报告间隔期间存在的收集器报告。删除不再使用的代理和收集器，并移动收集器而不是重新创建它们，以便新旧收集器不会重叠。 
|===
